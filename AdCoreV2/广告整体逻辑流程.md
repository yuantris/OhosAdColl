# AdCoreV2 广告 SDK 整体逻辑流程

> 入口：`RequestApplication`（AbilityStage）→ `ADHelper.init()` → 平台初始化 → 广告加载/展示/降级
>
> 本文基于源码整理，代码路径均相对于 `AdCoreV2/src/main/ets/ohos/`。

---

核心设计：

- **逻辑广告位（slot）与真实广告 ID 解耦**：业务只传 `splash` / `video` / `lscr` / `info` / `info_left` 等槽位名，由 `AdSlotManager` 按平台翻译为各广告平台的真实 ID。
- **单平台运行 + 降级切换**：V4/V5 下发的 `ss` 字段决定启用哪个平台，运行期失败时按优先级列表逐平台降级重试。
- **独立型广告（IndependentAd）**：开屏/视频/插屏均为"加载→校验→展示"的独立实例，当前实例仅保留一个，新加载前销毁旧实例。

## 二、启动阶段（RequestApplication）

文件：`application/RequestApplication.ets`

宿主应用继承 `RequestApplication`（AbilityStage），SDK 在应用 `onCreate` 中完成预初始化：

```
onCreate()
 ├─ setNetContext(this.context)          // 注入网络上下文（RCP）
 ├─ ZyNetLogger.setPretty(true)          // 网络日志格式化
 ├─ 注册 abilityLifecycle 回调
 ├─ appConfig = getAppConfig()           // 抽象方法：宿主返回 AppConfig
 ├─ 友盟 preInit()
 ├─ preInitBefore()                      // 抽象回调：宿主自定义预初始化
 ├─ validateConfig()                     // ★ 解析 info.json，配置广告位
 └─ autoNetworkConfig()                  // ★ 自动配置网络参数
```

### 2.1 validateConfig —— 广告位配置（本地/云创两条路）

读取 `info.json` 后按 `AdSwitchManager.enableEasyConfig` 分流：

| 模式 | 解析器 | 说明 |
| --- | --- | --- |
| V4 传统模式（`enableEasyConfig=false`） | `V4ConfigParser.configAdSwitchManager(info.json[0])` | 固定槽位：`splash/info/info_left/lscr/video`，一槽一 ID |
| 云创模式（`enableEasyConfig=true`） | `EasyConfigParser.configEasyAdSwitchManager(info.json)` | 从配置的 modules 中提取多槽位多 ID（ban/info/info_left/video/lscr/splash），写入 `AdHub` 后批量注册到 `AdSlotManager` |

两个解析器最终都会：

1. 填充 `AdIdStore`（APPID / VID / SID / VJUMP、各平台 appId 与广告位 ID）。
2. 向 `AdSlotManager` 注册 `slot → {平台 → 真实广告ID}` 映射。
3. 云创模式额外支持 `enableBanMerge`：华为平台 banner 复用 `info_left` 的 ID。

### 2.2 autoNetworkConfig —— SDK 网络参数

`AdSwitchManager.enableAutoNetConfig=true` 时调用 `NetBasic.setAllConfig(...)`，注入：

- `SID`（站点 ID）、`SV`（TokenCalculator.parseSV 签名版本）、`IT`（TokenCalculator.getV4It）
- `MARKET_NAME`、`PACKAGE_NAME`、`DEVICE_ID`

这些参数后续参与 V4/V5 开关请求的签名。

### 2.3 生命周期联动

| 回调 | 行为 |
| --- | --- |
| `onAbilityCreate` | `Ohos.init(ability.context)`（全局上下文）、`TestLog.updateMode`（测试环境切换测试广告 ID） |
| `onWindowStageCreate` | 保存 `windowStage` 供全局使用 |
| `onWindowStageActive` | 获取全局 `uiContext`；`handleWarmStart()` 热启动检测；`LifecycleManager` 分发窗口活跃事件 |
| `onAbilityBackground` | 记录退后台时间 `SDKConst.updateBackgroundTime(now)` |

### 2.4 热启动判定（handleWarmStart）

```
onWindowStageActive
  └─ handleWarmStart()
       └─ 后台时长 = now - lastBackgroundTime
            └─ 时长 > appConfig.getAdShowWaitingTime()
                 └─ HotStartManager.pushSplashAdPage()   // 弹热启动开屏
```

## 三、初始化阶段（ADHelper.init）

文件：`helper/core/ADHelper.ets`

在隐私政策授权后由宿主调用 `ADHelper.getInstance().init()`（幂等，`isInitialized` 防重入）：

```
init()
 ├─ 友盟 init()
 ├─ requestOAID(context)                    // 获取 OAID → OAIDStore
 │
 ├─ [V4] SDKCore.requestOFF()               // enableEasyConfig=false
 │  └─ zyClient.with().urlPath(V4).setToken(V4).post<ZyOFF>()
 ├─ [V5] SDKCore.requestEasyOFF()           // enableEasyConfig=true（云创）
 │  └─ zyClient.with().urlPath(V5).addHeader('y',ycid).setToken(V5).post<ZyOFF>()
 │
 ├─ TestLog.checkUpdateAllSlotToTestAdId()  // 测试环境校验/切换测试广告 ID
 ├─ availAd = AdModeManager.getAvailableAdPlatforms(OFF)   // 解析 ss/c/h/t
 ├─ 构建 platformConfigs：CSJ / TENCENT / HUAWEI（appId + debug）
 ├─ platformManager.init(platformConfigs, availAd)
 │    ├─ 按 availAd 过滤平台 → AdPlatformFactory.createPlatform()
 │    ├─ platform.init(config)
 │    ├─ currentPlatform = 第一个可用平台
 │    └─ initAdManagers()：创建 4 个广告 Manager（绑定当前平台）
 ├─ healthChecker.start()                   // 每 60s 熔断恢复巡检
 └─ isInitialized = true
```

### 3.1 开关请求（V4 / V5）

`application/SDKCore.ets`：

- **requestOFF（V4）**：POST 请求获取 `ZyOFF`；若 `enableDynamicAD`，调用 `ConfigVerifier.verifyConfigAdSwitchManager(off)` 用服务端下发动校/替换本地 info.json 配置。
- **requestEasyOFF（V5）**：V5 额外携带云创 `ycid` 请求头；同时校验 VIP 有效性（`off.d` 时间戳 > 本地 `ltime` 则解除 VIP）；`enableDynamicAD` 时走 `verifyEasyConfigAdSwitchManager`。
- **模式决策**（`AdModeManager.getADMode`）：
  - `ss` 字段为平台优先级字符串（`1`=穿山甲，`2`=腾讯，`4`=华为），逗号分隔；
  - 结合 `off.c / off.t / off.h` 开关位取第一个可用平台；
  - `ForceChannelManager` 强制渠道优先级最高（调试用）；
  - 结果写入 `AdSwitchManager.setAdPlatformFlags(isCsj, isHw, isTx, adOpen)` —— **这是广告总开关 `isAdOpen` 的唯一赋值点**。

### 3.2 广告位映射（AdSlotManager）

`slot → Map<PlatformType, 真实广告ID>`。加载时由 `platformManager.getRealAdId(slot, platform)` 完成翻译；debug + 测试开关打开时整表替换为各平台测试 ID。

## 四、广告加载阶段（统一降级编排）

四种广告的加载入口（`ADHelper`）：

| 方法 | 槽位 | 特殊前置 |
| --- | --- | --- |
| `loadSplashAd(listener)` | 固定 `splash` | 无 |
| `loadVideoAd(adId, rewardListener)` | 外部传入（一般 `video`） | **VIP 用户直接返回空结果**；错误监听收敛为静默监听（仅 `NO_FULL_VIDEO` 透传） |
| `loadInterstitialAd(adId?, listener)` | 默认 `lscr` | **VIP 用户直接返回空结果** |
| `loadFeedAd(config)` / `preloadFeedAd` | 外部 AdConfig | 走 `loadAd`（含缓存） |

统一流程（`DegradationStrategy.executeWithDegradation`）：

```
executeWithDegradation(config, loadCallback, listener)
 ├─ 1. 全局开关检查：!AdSwitchManager.isAdOpen → onAdShowError(AD_CLOSE)，返回空结果
 ├─ 2. 可用平台为空 → onAdShowError(AD_LOAD_FAILED)，返回空结果
 ├─ 3. 强制渠道开启 → executeForcedChannel()（单平台无限重试循环）
 ├─ 4. 正常流程 → executeWithPriorityList()
 │
 │   for platform of 平台优先级列表（config.platformPriority ?? 可用平台）:
 │     ├─ 熔断检查 isPlatformAvailable(platform, adType, slot)
 │     │     └─ 不可用 → 记录 SKIPPED 尝试记录，跳过该平台
 │     ├─ switchToPlatformByType(platform)   // 切换当前平台并重建 4 个 Manager
 │     ├─ listener.onAdPlatformSwitchStart(prev, cur)
 │     └─ while (!shouldDegrade):            // 平台内重试
 │          ├─ config.setAdId(AdSlotManager.getRealAdId(slot, platform))
 │          ├─ ad = await loadCallback(config, retryCount)
 │          │     └─ Manager.loadIndependentAd → platform.createXxxAd → ad.load()
 │          ├─ 成功 → 记录 SUCCESS，onAdPlatformSwitchSuccess，返回 AdResult(ad, records, platform, 耗时)
 │          └─ 失败 →
 │               ├─ 记录 FAILED（AdError code/message + RetryType）
 │               ├─ platformManager.recordPlatformFailure(...)   // 熔断计数 +1
 │               ├─ action = RetryStrategyManager.determineAction({platform, errorCode, retryCount...})
 │               ├─ RETRY   → retryCount < maxRetry ? retryCount++ : shouldDegrade=true
 │               ├─ DEGRADE → shouldDegrade=true（换下一个平台）
 │               └─ FAIL    → 立即返回失败结果
 │
 └─ 全平台失败 → CallbackGuard.guard('onAdShowError', AD_LOAD_FAILED)，返回空 AdResult
```

要点：

- **熔断机制**（`PlatformManager`）：同一 `平台:广告类型:槽位` 失败计数 ≥ **3 次**即标记不可用；60 秒后自动恢复（`isPlatformAvailable` 内惰性判断 + `HealthChecker` 每 60s 主动 `resetPlatformStatus`）。
- **重试策略**（`RetryStrategyManager` + `PlatformRetryStrategy`）：按平台差异化决定 RETRY / DEGRADE / FAIL，默认重试上限 `AdConstants.DEFAULT_MAX_RETRY`。
- **尝试记录**（`AdAttemptRecord`）：每次尝试（SUCCESS/FAILED/SKIPPED）均记录平台、序号、错误码、耗时、真实广告 ID、重试类型，最终汇入 `AdResult.attemptRecords` 并通过 `reportLog` 写入 `GlobalAdLoadLogStore`（调试组件可视化）。
- **回调防重**（`CallbackGuard`）：保证 `onAdShowError` 等回调只触发一次。

### 4.1 Manager 层加载细节

`SplashAdManager / VideoAdManager / InterstitialAdManager.loadIndependentAd` 三者结构一致：

```
旧实例存在 → destroy() 置空
currentAd = platform.createSplashAd / createVideoAd / createInterstitialAd(config)
currentAd.setAdListener(listener)
await currentAd.load()          // 真正请求广告平台 SDK
isValid() 不通过 → destroy + 返回 null（上层降级）
```

`FeedAdManager.loadAd` 则是唯一带缓存的路径：

```
AdCache.getValidAd(config)  → 命中直接返回
未命中 → platform.loadFeedAd(config) → setAdConfig → addToCache（容量 5，超限淘汰最旧并 destroy）
失败 → onLoadFail（返回 null）→ 抛错交由上层降级
```

### 4.2 平台层加载细节（以华为为例，`platform/HuaweiAdPlatform.ets` + `loader/HwAdLoader.ets`）

- `HuaweiIndependentAd.load()` 按 adType 分发到对应 Loader：
  - `splash` → `HwSplashAdLoader`（adType=1，请求成功返回 `ads + displayOptions` 供 UI 渲染）
  - `video` → `HwRewardVideoAdLoader`（adType=7）
  - `interstitial` → `HwInterstitialAdLoader`（adType=12，**加载成功后立即 `advertising.showAd` 自动展示**，并注册 PPS 接收器）
- 每个 Loader 内部带 `AD_LOAD_TIMEOUT_MS` 超时保护，超时返回 `AD_TIMEOUT` 失败结果。
- 请求参数统一携带 `OAIDStore.OAID`。
- 失败统一抛 `AdError(code, message)`，由降级策略捕获。
- 信息流：`HuaweiFeedAd.load()` 直接 `advertising.AdLoader.loadAd`（原生 adType=3），渲染交由 `FeedAdComponent` 的 AdComponent。

## 五、广告展示阶段

### 5.1 开屏（冷启动/热启动共用）

```
ZySplashShowPage（命名路由子窗口页）
 ├─ aboutToAppear → ADHelper.loadSplashAd(adListener)
 │     成功 → this.ad = result.ad
 ├─ build → SplashAdComponent(ad, adListener)
 │     ├─ 华为广告：AdComponent(ads, displayOptions, interactionListener)
 │     │    ├─ onAdOpen  → 清超时定时器 + onAdShow
 │     │    ├─ onAdClick → onClick
 │     │    ├─ onAdClose → 清定时器 + onAdClose（→ 销毁子窗口 finishSplashAd）
 │     │    ├─ onAdFail  → onAdShowError(AD_TIMEOUT)
 │     │    └─ 组件级 10s 超时兜底（仅保护华为渲染路径）
 │     └─ 非华为广告：平台 SDK 自绘全屏，不经本组件（加载超时由各自 Loader 管理）
 └─ aboutToDisappear
      ├─ HotStartManager.warmStartDetector()   // 顺带预加载插屏
      └─ HotStartManager.onSplashAdFlush()     // AdStateManager.refreshAds() 刷新活跃广告
```

背景：子窗口背景透明，`SplashAdComponent` 以启动图（`appConfig.getLauncherBgRes()`）为底，广告未就绪时视觉上仍是启动页。

### 5.2 热启动开屏（HotStartManager.pushSplashAdPage）

```
检查 isAdOpen → false 直接跳过
检查所有启用平台下 'splash' 槽位是否存在有效 ID → 全空跳过
getWindowStage().createSubWindow("ZySplashShowPage")
  → loadContentByName('ZySplashShowPage')
  → 背景透明 + showWindow()
```

### 5.3 激励视频 / 插屏

- 激励视频：加载成功后由平台 Loader 直接拉起全屏播放（华为经 `RewardAdStatusHandler` 转发 show/click/complete/reward 事件到 `OnVideoRewardListener`）。
- 插屏：华为在 Loader 加载成功回调内直接 `advertising.showAd` 展示；关闭/事件经 `InterstitialAdStatusHandler` 分发。

### 5.4 信息流 / Banner

- `loadFeedAd` 返回 `AdResult<IAd>`（优先走缓存），业务在 `FeedAdComponent` / `BannerAdComponent` 中绑定 ad 实例渲染（华为经 AdComponent，展示、点击、销毁事件回传）。
- `preloadFeedAd` 仅预加载入缓存，不返回实例。

## 六、销毁与资源管理

- `destroySplashAd() / destroyVideoAd() / destroyInterstitialAd()`：销毁对应 Manager 的 `currentAd`（触发 `onAdDestroy`）。
- `AdCache`：容量上限 5 条/槽位，FIFO 淘汰并 destroy；`clearExpiredAds` 按 `CachedAdEntry.isCacheExpired` 清理，30s 定时巡检。
- 热启动开屏页关闭时 `destroyWindow()` 释放子窗口。
